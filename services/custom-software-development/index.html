Custom software development

I build custom software for business forms, data workflows, dashboards and internal tools. Smaller, clearly scoped projects start at KSh 40,000 or $400. I am John Mwaura, known as Dev John, an independent full-stack developer in Kenya.

When a business workflow needs its own software

A spreadsheet can hold records, but it may become difficult to manage when several people need to update them or follow different rules. A custom application can put the forms, records and actions in one place. The useful starting point is the task that staff repeat and the information they need to complete it.

Internal tools can cover order workflows, booking processes or administrative tasks. Dashboards can bring relevant records into a readable view. Role-based access can control which parts people use when that is part of the requirements. These are possible project directions, with the actual features defined in the scope.

Smaller projects and advanced platforms

The Custom Software package starts at KSh 40,000 or $400 for smaller, clearly scoped projects. It lists custom functionality, business forms and data-management workflows, a suitable admin interface where required, basic reporting or dashboards where appropriate, a responsive web interface, deployment and handover.

That starting figure is not a price for an entire marketplace or SaaS product. Advanced Platforms and Custom Products uses a custom quote for multi-vendor marketplaces, SaaS, booking and reservation platforms, business management systems, advanced dashboards and complex API integrations.

The boundary depends on what the product must do. A limited form and reporting workflow can have a clear edge. A platform with several kinds of users, linked transactions and many external dependencies needs a broader discussion. I would rather define those parts in writing before attaching a package name to the project.

How I scope an application

Describe one current process using a real example with sensitive information removed. Explain who starts it, which records they enter, what another person reviews and what result is needed. If different people have different access, describe those responsibilities in ordinary language.

We can then identify the forms, data, admin screens and connections the project needs. The written scope and quote provide a reference for the build and review. An existing system may need integration work; a new product may need its database designed from the beginning. Neither should be assumed from a short feature label.

The stack behind the interface

My full-stack tools include React, Next.js, TypeScript and Node.js, with PostgreSQL, Supabase and Prisma for data work. Authentication tools on my homepage include JWT, OAuth, role-based access control and row-level security policies. Docker and GitHub Actions are part of the deployment stack.

The tool choice follows the project. An internal reporting view, a document application and a public-data platform do not have identical needs. The portfolio entries show the stacks of those actual projects. For connected conversations and payments, the requirements may also involve the WhatsApp Cloud API, M-Pesa Daraja or Stripe.

Can the application replace a spreadsheet workflow?

That is a useful kind of problem to discuss. Explain the records, users and actions involved so the required forms and reporting can be scoped.
